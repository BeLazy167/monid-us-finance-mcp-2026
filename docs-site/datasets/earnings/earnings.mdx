---
title: "Earnings"
description: "Earnings records composed from SEC filing events, not a separate earnings-calendar feed."
openapi: "api-reference/openapi.json GET /earnings"
---

There is no dedicated earnings dataset behind this route. An earnings record here is composed from SEC filing events, 8-K, 10-Q, and 10-K, matched to the period they report on. Pass `ticker` for one company's recent filings. Omit `ticker` for the real-time feed instead. It returns the most recently filed earnings across covered companies, sourced from the Nasdaq earnings calendar and deduplicated by ticker.

The same `report_period` can show up twice if a company files an 8-K earnings announcement and the matching 10-Q lands separately. The 8-K sorts first, since it is usually the earlier of the two filings.

## What this answers

- What a company reported for its most recent quarter, and whether it beat or missed an estimate, when the underlying filing includes one.
- Which companies have filed earnings most recently, across the covered universe.

## Coverage

| | |
|---|---|
| Provider chain | DefiLlama `/equities/v1/statements` and `/equities/v1/filings`, composed into filing-event records. No-ticker mode adds the Nasdaq earnings calendar |
| Measured cost | \$0.0012 per call (statements plus the filings composition) |
| Cache TTL | 600 seconds, see [Caching](/guides/caching) |

## Query rules

`ticker` is optional. `limit` is accepted for parameter parity with the underlying `limit` query parameter, but the tool behind this route ignores it and always returns up to 5 records regardless of the value passed. This is a REST-parity quirk, not a REST default mismatch like the ones on the statement routes.

Records only cover 10-K and 10-Q filing events. 8-K earnings releases that have not yet been followed by a matching 10-Q, and the real-time feed's underlying calendar coverage, are narrower than a dedicated earnings-calendar API. A block whose period is missing from the underlying statements matrix is left out of the record rather than filled with an estimate.

`filing_datetime` is declared on this record for Financial Datasets-contract parity, but no provider integration in this codebase currently sets it. It is always omitted in practice.

## Worked example

This repo has no committed live capture for `/earnings`. The example below is illustrative only, field names follow `go/fd/types.go` and `go/providers/earnings.go`, values are synthetic placeholders, not a real filing or a real reported figure.

```bash curl
curl -s 'https://monid-finance-api.fly.dev/earnings?ticker=AAPL' \
  -H 'X-API-KEY: <your-api-key>'
```
