"Compatible" on this site means the request and response shapes match the Financial Datasets interface closely enough that an existing client can switch base URLs and keep working. It does not mean every route is implemented, and it does not mean the two servers behave identically everywhere they overlap. This page is the itemized version of that claim.

Monid Finance MCP is an independent, Monid-backed implementation. It is not affiliated with or endorsed by Financial Datasets, and no Financial Datasets data or code is used.

## Tool status

All 27 MCP tool names are registered and answer a well-formed call. They split into three groups.

<Tabs>
  <Tab title="Live, 16 tools">
    Implemented, unit tested, and confirmed against production Monid with real paid calls.

    `get_company_facts`, `get_income_statement`, `get_balance_sheet`, `get_cash_flow_statement`, `get_financial_metrics_snapshot`, `get_financial_metrics`, `get_filings`, `get_filing_items`, `list_filing_item_types`, `get_stock_prices`, `get_stock_price`, `get_news`, `get_earnings`, `get_insider_trades`, `screen_stocks`, `list_stock_screener_filters`
  </Tab>
  <Tab title="Implemented, unverified live, 7 tools">
    These call real Monid providers and return real data. The unit test suite covers them against mocked provider responses, but no paid production call has confirmed their output yet the way it has for the 16 tools above.

    `get_segmented_financials`, `get_kpi_metrics`, `get_kpi_guidance`, `get_kpi_non_gaap`, `get_interest_rates`, `get_index_fund`, `get_institutional_holdings`

    <Note>
      These are working tools, not stubs. Call them over MCP. Their REST paths are not wired yet, which is a routing gap, not an implementation gap. See the table below.
    </Note>
  </Tab>
  <Tab title="Not implemented, 4 tools">
    Registered with their Financial Datasets parameters. Every call answers a typed error at zero cost. No Monid call is made.

    `get_beneficial_owners`, `get_beneficial_ownership`, `get_insider_ownership`, `get_institutional_investors`
  </Tab>
</Tabs>

## REST covers less than MCP

The REST facade wires 15 of the 27 tools to a path. The rest, including `list_filing_item_types` and the 7 tools listed above, are MCP only right now. Their REST paths exist for interface parity and always answer the zero-cost `not_implemented` stub, even for the 7 tools that work over MCP.

| REST path | Behavior | MCP tool that works today |
|---|---|---|
| `/kpi/metrics`, `/kpi/guidance`, `/kpi/non-gaap` | Stub, HTTP 200 | `get_kpi_metrics`, `get_kpi_guidance`, `get_kpi_non_gaap` |
| `/macro/interest-rates*` | Stub | `get_interest_rates` |
| `/financials/segments`, `/financials/*/segments` | Stub | `get_segmented_financials` |
| `/index-funds*` | Stub | `get_index_fund` |
| `/institutional-holdings`, `/institutional-holdings/tickers` | Stub | `get_institutional_holdings` |
| `/institutional-holdings/investors` | Stub | None, `get_institutional_investors` is a real stub |
| `/insider-ownership`, `/beneficial-ownership`, `/activist-ownership` | Stub | None, the underlying tools are real stubs |

If a REST route answers `not_implemented`, check [MCP Tools](/mcp-tools/overview) before assuming the data does not exist. It may only mean the REST path is not wired yet.

## REST and MCP disagree on defaults

The same tool can return different data depending on which transport called it, if you rely on a default instead of passing the parameter.

`get_income_statement`, `get_balance_sheet`, `get_cash_flow_statement`, and `get_financial_metrics` default `period` to `ttm` in the MCP tool schema, matching the published Financial Datasets schema. The REST route for the same data defaults an omitted `period` to `annual` instead, because the REST handler always fills a value before calling the tool. Pass `period` explicitly on both transports.

`get_filings` defaults `limit` to `100` over MCP and to `10` over REST, for the same reason.

## Response contract

A success response contains only Financial Datasets schema keys, in schema property order. A field the server cannot source is left out, never set to null or guessed. Every failure uses the Financial Datasets `{"error": <code>, "message": <text>}` shape, covered in full in [Errors](/guides/errors). Pagination follows the pattern in [Pagination](/guides/pagination). Cost and provenance never appear in a response body. They go to an internal receipts ledger, one row per Monid call.

## Known gaps, endpoint by endpoint

<AccordionGroup>
  <Accordion title="Company lookup is ticker only">
    `cik` is accepted for parity but answers `bad_request`. `get_company_facts` currently sources ticker and name only.
  </Accordion>
  <Accordion title="News needs a ticker">
    `get_news` requires `ticker`. Market-wide news is not routed.
  </Accordion>
  <Accordion title="TTM statements are computed, not sourced">
    Trailing-twelve-month rows are built locally from four consecutive quarters. Flow fields are summed, weighted-average shares are averaged, and balance-sheet fields carry over from the final quarter rather than being recomputed. TTM rows omit `fiscal_period` and `currency`.
  </Accordion>
  <Accordion title="Prices: ascending order, local aggregation, single interval multiplier">
    `get_stock_prices` returns ascending time order. Week, month, and year bars are aggregated locally from daily bars. `time` is the bar's end date in UTC. `interval_multiplier` must be `1`.
  </Accordion>
  <Accordion title="Filing exhibits are not sourced">
    `get_filing_items` accepts `include_exhibits` for parity, but a `true` value answers `bad_request`. Exhibit content is not implemented.
  </Accordion>
  <Accordion title="Filing type is a closed list">
    `get_filings` validates `filing_type` against `10-K`, `10-Q`, `8-K`, `20-F`, `6-K`. Other Financial Datasets filing types, like `DEF 14A`, are rejected.
  </Accordion>
  <Accordion title="Earnings composition is narrower">
    `get_earnings` composes records from 10-K and 10-Q filing events only. 8-K earnings releases and the market-wide, no-ticker feed are not routed. Records omit any block whose period is not present in the underlying statements matrix.
  </Accordion>
  <Accordion title="Financial metrics omit market-derived valuation fields">
    `get_financial_metrics` leaves out fields that need a historical market price we do not have: `enterprise_value`, `price_to_*` ratios, EV multiples, `free_cash_flow_yield`, `peg_ratio`, `return_on_invested_capital`, `currency`, `filing_datetime`. TTM rows also omit filing identity, since a TTM window spans more than one filing.
  </Accordion>
  <Accordion title="Insider trades are capped at 15 rows">
    Financial Datasets allows up to 5000 rows. This server caps at 15, the size of the validated SEC Form 4 feed it reads. `form_type` filtering is rejected, because the underlying route does not report form types. `name` is the raw insider relationship text, not a normalized name. `title`, `transaction_code`, `security_title`, and `shares_owned_before_transaction` are omitted.
  </Accordion>
  <Accordion title="Screener supports two fields">
    `screen_stocks` executes `exchange` and `market_cap` filters with the `eq` operator, through the Nasdaq screener. Any other field or operator answers `bad_request` before any Monid call runs. `list_stock_screener_filters` lists only these two filters, not the full Financial Datasets catalog.
  </Accordion>
  <Accordion title="Some fields are always omitted">
    CIK, currency, and EBITDA on income statements are examples. These fields are schema-legal and optional in Financial Datasets, so omitting them is a valid response, not a broken one.
  </Accordion>
</AccordionGroup>

## Should you migrate an existing integration

If your integration only touches the 16 live tools and does not depend on the omitted fields above, pointing your base URL and key here is close to a drop-in swap. If you depend on `cik` lookups, market-wide news, `as_reported` statements, or any of the 4 stubbed ownership tools, this API will not cover you yet. File an issue on [GitHub](https://github.com/BeLazy167/monid-us-finance-mcp-2026) if you need one of those.
