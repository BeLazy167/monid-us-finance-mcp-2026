List-returning REST endpoints, statements, financial metrics, filings, prices, news, earnings, insider trades, page with an opaque cursor. This matches the Financial Datasets pagination style, so existing pagination code should work unchanged.

## The mechanics

`limit` sets a budget for the whole request, not a page size. Pass it once, on the first call. Each response page holds a fixed number of records regardless of what `limit` you asked for: 10 for most list endpoints, 100 for `/prices`. If your `limit` is larger than one page, the response carries a `next_page_url` you follow for the next page, until either `limit` is reached or the data runs out.

The `cursor` value inside that URL is a small base64url-encoded JSON object holding one field, a record offset. Decode `eyJvIjoxMH0` and you get `{"o":10}`, meaning "start from record 10." Nothing about that format is documented as stable, so treat the cursor as opaque and pass it back exactly as given rather than constructing your own.

<CodeGroup>
```bash First page
curl -s 'https://monid-finance-api.fly.dev/filings?ticker=AAPL&limit=25' \
  -H 'X-API-KEY: <your-api-key>'
```

```json Response, trimmed
{
  "filings": [ ],
  "next_page_url": "https://monid-finance-api.fly.dev/filings?ticker=AAPL&cursor=eyJvIjoxMH0"
}
```

```bash Next page
curl -s 'https://monid-finance-api.fly.dev/filings?ticker=AAPL&cursor=eyJvIjoxMH0' \
  -H 'X-API-KEY: <your-api-key>'
```
</CodeGroup>

`next_page_url` always points back at the host you called. If you called `https://monid-finance-api.fly.dev`, the link stays on that host. It never sends you to a different domain.

When no more records remain, `next_page_url` is left out of the response entirely.

## Invalid cursors

A `cursor` value this server did not mint, hand-edited, corrupted, or expired in some format we do not use, gets a `400`.

```json
{
  "error": "invalid_cursor",
  "message": "cursor is not a valid opaque pagination token"
}
```

## MCP does not paginate

An MCP tool call returns a bare result, an array for list tools, an object for snapshot tools, with no `cursor` and no `next_page_url`. Pagination is a REST concept here. Use the tool's own `limit` parameter to bound how much comes back.

Some list tools cap their result size below what the REST page mechanics above would suggest. `get_insider_trades` returns at most 15 rows no matter what `limit` you pass, because the underlying validated feed only has 15 rows to give. See [Coverage](/overview/coverage) for per-tool caps like this one.
