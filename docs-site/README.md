# docs-site: Mintlify documentation

This is the Mintlify-based documentation site for Monid Finance MCP. It replaces the hand-rolled static site in `../website/` with a modern docs UI: left nav, right-hand table of contents, code tabs, cards, and an API playground generated from the OpenAPI spec.

`../website/` is still the live, deployed docs site (`https://monid-us-finance-mcp-2026.vercel.app`). Do not delete or modify it until this Mintlify site has replaced it in production.

Each `datasets/*.mdx` page carries `openapi:` frontmatter bound to its primary REST operation, which turns on the endpoint pill and request playground for that route. The full, unfiltered set of 34 endpoints (15 implemented, 19 registered but not implemented) is also browsable in the **API Reference** tab, auto-generated from the same spec.

## The OpenAPI spec

`docs.json` wires the **API Reference** tab to `api-reference/openapi.json`, and every `datasets/*.mdx` page references the same file by relative path in its frontmatter. The copy in this directory is a verbatim copy of `docs/openapi.json`. It once differed by one line: `info.license` carried both `identifier` and `url`, which OpenAPI 3.1 forbids (a license object takes one or the other). That was fixed upstream, so the two files are now byte-identical and re-copying needs no follow-up edit. Verify with `shasum docs/openapi.json docs-site/api-reference/openapi.json` after copying.

To refresh the copy:

```bash
cp docs/openapi.json docs-site/api-reference/openapi.json
# then remove info.license.url from the copy, or fix it upstream first
```

## MCP Tools page is generated, not hand-typed

`mcp-tools/overview.mdx` is generated by a script that reads `go/mcpserver/tool_schemas.json`, the 27 MCP tool schemas the server actually embeds and advertises, and emits one section per tool with its parameters, types, required flags, and defaults. If that JSON file changes, regenerate this page instead of hand-editing it: load the array, group tool names by dataset category, and render one Markdown table per tool from each `inputSchema.properties` entry. The wrapper text around the generated tables (the intro, the status legend, the two callouts) is hand-written and should be edited directly.

## Preview locally

```bash
npm i -g mint
cd docs-site
mint dev
```

This starts a local preview (default `http://localhost:3000`) with hot reload on every `.mdx` or `docs.json` change.

```bash
mint broken-links   # check for broken internal links before shipping
mint validate        # validate docs.json and the referenced OpenAPI spec
```

Note: the Mintlify CLI does not run on Node 25+. If your default Node is newer, install an LTS release alongside it (for example `brew install node@24`) and run `mint` with that version on `PATH` for these commands.

## Deploy

**Recommended, Mintlify Starter plan (free) plus GitHub app:**

1. Create a Mintlify account at [mintlify.com](https://mintlify.com), a human needs to do this, see below.
2. Install the Mintlify GitHub app on this repository and point it at `docs-site/` as the docs root.
3. Push to `main`. Mintlify builds and deploys automatically on every push that touches `docs-site/**`.
4. Once the new site is live and verified, point the production docs domain (`monid-us-finance-mcp-2026.vercel.app`, or a new custom domain) at the Mintlify deployment, and only then retire `../website/`.

**Alternative, CLI deploy**, if the Mintlify CLI's `deploy` command is available on your plan:

```bash
cd docs-site
mint deploy
```
